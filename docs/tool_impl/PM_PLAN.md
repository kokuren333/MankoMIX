## 0. 結論（先に）

1. 143 件は「143 個のプロセッサ」ではない。**全 143 件は、新プロセッサ型 120（うちコンポジット 5）、新 op 18（編集段 12・mix 段 6）、新コマンド 16、新しい観察量 3、新しい型を作らず欄・共通ブロック・既存の新型で満たすもの 7（T01-15、T02-02、T03-11、T04-08、T10-05、T10-06、T12-01）** に畳める。内訳：前任の 47 件＝型 43（コンポジット 2）・op 2・コマンド 3・型なし 4／追補の 96 件＝型 77（コンポジット 3）・op 16・コマンド 13・観察量 3・型なし 3。
2. 先に作るのは 26 個の共有部品（§3 の BB-00〜17 と §3.2 の BB-18〜25）。143 件のうち 127 件は部品が出来れば S〜M の組み立てになる（S 64・M 63）。重いのは 16 件（L）：前任分の 7 件（共振抑制、自動スペクトルバランス、適応型リミッター、シマー、ピッチ遅延、スプリング、ビンテージ・デジタル残響）と、追補分の 9 件（バイノーラル、テープ、アンプ、自動ピッチ補正、音符編集、ポリフォニック再調律、デリバーブ、ワウ補正、ボーカル整列）。
3. 既存 21 プロセッサ、既存 op、床、ゲート定義、マスター最終段は変えない。変えたくなる案は §8 に隔離した。
4. 実装開始は FB2 完了確認後（§7）。
5. カタログは完全版になり、143 件すべてに spec がある（`spec/01`〜`12`）。タグの内訳：A 75・B 41・C 4・D 23。ウェーブの内訳：W1 21・W2 54・W3 41・W4 23・W5 4。
6. （追補）カテゴリ 5〜12 で足した規則は 1 つ：**プロセッサは「1 入力・同じ長さ」だけ。長さが変わる・別トラックの音が要る・区間を作り替える処理は、編集段の op が派生クリップを作る**（BB-18、`spec/08` §0.1）。

### 3.1 BB-00 契約の追加（唯一、既存ファイルの形に触る部品）

| 追加 | 形 | 規則 |
|---|---|---|
| 型 `curve` | `[[x, y], …]`。宣言に `x_unit`・`x_min/max`・`y_min/max`・`max_points`（型ごとに宣言。上限 65536） | x は狭義昇順。範囲 `[下限, 上限]` で書けない。較正の対象外（配列と同じ扱い） |

## 5. 学習系（タグ C）の「完全実装」の定義

「完全実装」とは次の 6 条件を満たすことで、**モデルの学習・再学習・微調整は範囲外**。

| # | 条件 | 中身 |
|---|---|---|
| C-1 | ピニングした OSS モデルの組み込み | レジストリのエントリ（SPEC §12.2 の形）に、配布元 URL・sha256・サイズ・アーキテクチャ・コードの版（コミットかタグ）を固定。ウェイトは同梱せず初回取得、ハッシュ検証 |
| C-2 | 決定的な推論設定 | 推論は CPU を基準経路にする。ONNX Runtime（MIT）を第一候補に、版を固定、`intra_op=1`・`inter_op=1`、グラフ最適化レベル固定、入力のチャンク長・重なり・窓・パディングを固定、乱数を使う箇所はプロジェクト由来のシード。同一環境でビット一致を合格条件、環境をまたぐ場合は測定値の許容誤差内（SPEC §16.3）。GPU 経路は任意で、記録に実行プロバイダを残し、ビット一致を主張しない |
| C-3 | ライセンス記録 | コードとウェイトを別に記録（`license.code`／`license.weights`／`evidence`／`caveats`）。`official` にできるのは使用と再配布の両方がクリーンなものだけ。研究限定・非商用は BYOW のみ。学習データ由来の留保を `caveats` に書く |
| C-4 | モデル不在時のフォールバック | 定義に `fallback`（決定論 DSP の代替、または「実行しない」）を持つ。フォールバックが走ったことはレンダリング記録と Mix Report に出る。フォールバックが無い型は、モデル不在で明示エラー（黙って素通ししない） |
| C-5 | 表面 | プロセッサ（`offline_only: True`、`backends: ["model"]` を追加）か、コマンド。出力が音のものは、処理前後の測定を記録に残す |
| C-6 | テスト | モデル無しで回る単体（入出力の形、チャンク継ぎ目、フォールバック）と、モデルの場所を外から与えたときだけ回る任意テスト（2 回描画一致、既知入力の出力ハッシュ） |

## 6. 非プロセッサ（タグ D）の置き場

| 種類 | 置き場 | 規則 |
|---|---|---|
| 候補を出す道具（提案 EQ、マッチ曲線、低域の目標） | 下見コマンド `direction suggest …`／`direction ref …`。出力は「指揮書に貼れる手の候補」と根拠の測定値 | 読み取り専用。適用しない。使ったかどうかを機械は見ない。出力に当てになり度を付ける（DESIGN_PHILOSOPHY §6.3） |

| 編集（時間軸の切り貼り、整列、ピッチ・タイム編集） | 編集段の op（`edit_*`）と台帳 | 素材は書き換えない（クリップと台帳で表す。既存の編集段と同じ） |

（追補）表の「編集」の行を具体化した：長さが変わる・別トラックの音が要る・区間を作り替える処理は、編集段の op＋派生クリップ（BB-18。`spec/08` §0.1）。追補で足した編集段の op は 12（`edit_pitch`・`edit_stretch`・`edit_stretch_extreme`・`edit_varispeed`・`edit_reverse`・`edit_isolate`・`edit_debleed`・`edit_align_time`・`edit_align_pitch`・`edit_quantize`・`edit_fade`・`edit_normalize`）、mix 段の op は 4（`vocode`・`breath`・`drum_replace`・`level_phrases`）。ファイル間の変換でプロジェクトを読まないもの（`spatial ambi`）と、明示した場所に試聴・書き出しファイルを書く下見（`direction preview codec --out`、`direction extract midi --out`）は、FB2 の `listen pack --out` と同じ扱い（プロジェクトの正本・台帳には触れない）。

判断の原則：**信号を変えるならプロセッサか op、信号を読むだけなら下見か観察量、人が見るだけなら GUI。** 1 つのツールが複数にまたがるときは「測る部分」と「当てる部分」に割る（例：マッチ EQ ＝ 曲線を出す下見 ＋ `fir_eq`）。
