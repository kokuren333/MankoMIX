# spec/12 マスタリング／計測／リファレンス（9 件）

カタログ §12。共通規約は `spec/01_dynamics.md` §0。置き場の規則は PM_PLAN §6。タグは 2 代目 PM が付けた。

## 0. カテゴリ共通（**不変領域に最も近いカテゴリ。先に線を引く**）

1. **媒体プロファイル（`profiles/media_profiles.json`）、ゲート定義 4 ファイル、検証（verify・gate）、マスター最終段（`limiter`、S-06）、既存 `loudness_gain` は 1 バイトも変えない。** 本カテゴリの 9 件は全部、その外側に足す（PM_PLAN OD-8 は「触れない」で設計した）
2. 計測は「観察量の primitive」か「下見コマンド」。**合否・警告を作らない。** 既存の検証が既に測っている量（積分ラウドネス、トゥルーピーク、相関、DC ほか）と同じ量を出すときは、**既存の計測関数を呼ぶ**（別実装を作って値が食い違うことを避ける。実働は `verify` 側の実装を読んで合わせる）
3. プロファイルの値は**読むだけ**なら使ってよい（例：配信の目標値を下見の既定に引く）
4. マスター段へ置ける新プロセッサは `dc_remove`・`fade` の 2 つ（スロットは各件）。指揮書からマスター段へは置けない（OD-3）。最終段より後ろには何も置けない（OD-1・OD-12）
5. 顔の等価性（SPEC §16.1）：GUI に出す数値は全部、同じ値が CLI／MCP から取れる

**共通テスト（MS）**：(MS1) G0-3（ゲート定義・プロファイルの SHA-256 不変）を本カテゴリの全単位で個別に確かめる (MS2) 下見・計測は読み取り専用（プロジェクトのハッシュ一致。`--out` を書いたときだけ、その場所に書く） (MS3) 既存の検証と同じ量は、既存の値とビット一致 (MS4) CLI と MCP の等価性 (MS5) 再現一致

## T12-01 適応型マキシマイザー

**新しい型を作らない。T01-13 `adaptive_limiter`（spec/01）が本件そのもの**｜B｜W3｜S（T01-13 の受け入れに、下の試験を足すだけ）｜—

カタログ 1-13「適応型（ダイナミック）リミッター（Ozone Maximizer IRC／Elevate）」と 12-1「適応型マキシマイザー（Ozone Maximizer）」は同じ製品を指しており、同じ機能。違いは使う場所（マスター）だけ。

- マスターでの置き場：スロット 5（最終 `limiter` の前）。**最終段の代わりにはしない**（OD-1）。最終段の `limiter` は従来どおり掛かり、トゥルーピークの保証は従来どおり最終段が持つ
- 「音圧を上げる」操作：`adaptive_limiter.drive_db`。目標ラウドネスへ合わせるのは既存 `loudness_gain`＋検証の仕事で、本件は足さない
- 下見の追加（S）：`direction query limiter_headroom --project P`：マスターのスロット 5 に `adaptive_limiter` を `drive_db`＝0／1／2／…／12 で置いたと仮定したときの、積分ラウドネス・最大 GR・GR が 3 dB を超える時間の割合・低域 THD の推定、の表を出す（**置かない。仮定の描画を測るだけ**）。指揮者が「どこまで押すと何が起きるか」を数値で読める
- テスト：T01-13 の全項目＋ (1) マスターのスロット 5 に置いた描画で、最終 `limiter` の後のトゥルーピークが、置かない場合と同じ上限を満たす（既存 S-06 の検査がそのまま通る） (2) `drive_db=0`・天井未満の素材：置いた場合と置かない場合のマスター出力がビット一致 (3) `query limiter_headroom`：MS2・MS4・MS5、表の各行が、実際にその設定で描画した測定と一致
- 依存：T01-13

## T12-02 モノ互換チェック

**観察量の primitive 追加（`mono_loss`、`correlation_bands`）＋下見 `direction query mono`**｜D（カタログ：「既存の観察量の発展」）｜W4｜S｜Codex

既存の観察量・R-10 の「モノ合算損失」「相関」は変えない（MS3）。足すのは帯域別・時間別の分解。

- primitive `mono_loss`：`target`、`section`、`params.band`（`full`／1/3 oct の中心周波数／`lo,hi`）。値＝モノ合算（(L＋R)/2）のレベル − ステレオの平均パワーのレベル（dB。0＝損失なし、−∞＝完全な逆相）
- primitive `correlation_bands`：帯域（既定：<120／120〜500／500〜2k／2k〜8k／>8k Hz）ごとの相関係数の、時間方向の中央値・5 パーセンタイル・負の時間の割合（窓 400 ms）
- `direction query mono`：`--project`、`--target`（既定 `master`）、`--section`、`--by-track`（トラックごとに「マスターのモノ損失への寄与」＝そのトラックを抜いたときの損失の変化）、`--worst N`（損失の大きい時刻と帯域の上位）。出力：1/3 oct の損失の表、時間別の最悪区間、相関の表、`--by-track` の順位
- **「モノで崩れる」とは言わない**：数値と、どのトラックのどの帯域が寄与しているかだけ。直す手（`stereo` の低域モノ化、`band_pan`、`time_align` など）の候補も出さない（T02-07 のような提案系ではない。計測だけ）
- 正典：既存の実装が正（R-10 の定義）。相関は単純な正規化相互相関（既存と同じ定義を使う）
- テスト（MS に加えて）：(1) L＝R：全帯域で損失 0 dB・相関 1 (2) L＝−R：損失 ≤ −100 dB・相関 −1 (3) 片側を 0.5 ms 遅らせた広帯域雑音：損失の谷が 1 kHz・3 kHz・…（理論位置 ±1/6 oct） (4) `full` の値が既存の「モノ合算損失」とビット一致 (5) `--by-track`：1 本だけ逆相成分を持つ合成ミックスで、そのトラックが 1 位 (6) primitive を使わない指揮書はバイト同一
- 依存：BB-25

## T12-03 DC オフセット除去

`dc_remove`｜A｜W1｜S｜Codex｜`stages: ["track","bus","master"]`、`master_slot`：スロット 1 の先頭（EQ より前。実働がスロットの規則を読んで、既存の順序を変えずに置ける位置を確かめる。置けなければ master を外し、PM_PLAN OD-12 に合流）

| id | 型 | 単位 | 範囲 | 既定 |
|---|---|---|---|---|
| `mode` | e | — | `mean`／`highpass`／`off` | `off`（`off`＝ビット一致の素通し） |
| `cutoff_hz` | f | Hz | 1〜20 | 5（`highpass`） |
| `phase` | e | — | `minimum`／`zero` | `zero`（`zero`＝前向き・後ろ向きの 2 回掛け。オフラインだけ。位相を回さない） |
| `per_channel` | b | — | — | true |
| `threshold_db` | f | dBFS | −120〜−20 | −80（`mean`：|平均| がこれ未満なら何もしない＝ビット一致） |

- アルゴリズム：`mean`＝全長の平均を引く（`offline_only: True` を型に宣言。時間変化する DC には効かない）。`highpass`＝1 次の DC 阻止フィルタ（`zero` は 2 回掛けで実質 2 次）
- 既存の検証 S-09（DC が無いこと）は変えない。本型は「検出されたときに指揮者が置ける手」
- 記録：処理前後の DC（dBFS、チャンネル別）
- 正典：J. O. Smith『Introduction to Digital Filters』（DC ブロッカー）
- テスト：(1) `off`、および `mean` で閾値未満：ビット一致 (2) 正弦＋DC（−30 dBFS）：`mean` で DC ≤ −140 dBFS、正弦は不変（差が DC だけ） (3) `highpass`・`zero`：20 Hz で −0.5 dB 以内、DC ≤ −100 dBFS（10 s）、インパルス応答が対称 (4) `minimum`：レイテンシ 0 (5) ピークが増えうる（非対称波形から DC を引くと）ことを記録：処理後のピークを出す
- 依存：なし（BB-01 だけ）

### 実装時の確定（統括の判断 D-13）

`dc_remove` は既存slot1内で先頭を保証できないため安全側にtrack/bus限定とした（W1d、describe）。highpass/zeroのcutoffは最終応答の −3 dB角として2回通過を補正する。cutoff5 Hzで20 Hzの旧 −0.5264999827951059 dBから −0.22196813869600376 dBへ。zeroは有限長端の残留平均も除く。masterの順序規則は変更しない。

## T12-04 フェード／クロスフェード編集

**編集段の op `edit_fade`（クリップの頭・尾・編集点）＋プロセッサ `fade`（トラック・バス・マスターの時刻指定フェード）**｜D＋A｜W4（`fade` は W1）｜S｜Codex

op `edit_fade` の `params`：

| id | 単位 | 範囲 | 省略時 |
|---|---|---|---|
| `where` | 列挙 | `in`／`out`／`both`／`cross` | （必須。`cross`＝`section` の位置にある編集点〈隣り合う 2 クリップの境目〉） |
| `in_ms`・`out_ms` | ms | 0〜60000 | 10／10 |
| `cross_ms` | ms | 1〜5000 | 20（`cross`。境目を中心に、両側の素材をこの長さだけ重ねる。**素材に重ねる余白が無ければ拒否**） |
| `shape` | 列挙 | `linear`／`equal_power`／`s_curve`／`exp`／`log` | `in`・`out`：`s_curve`、`cross`：`equal_power` |
| `cross_law` | 列挙 | `auto`／`equal_power`／`equal_gain` | `auto`（重なる区間の両素材の相関を測り、≥ 0.5 なら `equal_gain`、未満なら `equal_power`。測った相関を記録） |
| `clip` | クリップ ID | — | トラックの全クリップ |

- `stage: edit`。台帳にフェードの形を持つだけ（派生クリップは作らない。描画時に掛ける）。既存 `edit_trim` が作る切り口の既定のフェードがあれば、それは変えない（実働が `DIRECTION_FORMAT` §7.1 を読んで、重ねて掛かる場合の順序を決め、記録する）
- テスト：(1) 形の関数が定義どおり（各 `shape` の中点の値、端点 0／1、単調） (2) `cross`・`equal_power`：無相関の雑音どうしで、重なり区間の RMS が前後 ±0.3 dB／`equal_gain`：同一信号どうしで ±0.01 dB (3) `auto` の切り替えが相関 0.5 の両側で正しい (4) 余白なしの `cross` は拒否 (5) `edit_fade` を含まない指揮書はバイト同一 (6) プロジェクトの尺が不変

`fade`（`stages: ["track","bus","master"]`、TV、`master_slot`：スロット 5）：

| id | 型 | 単位 | 範囲 | 既定 |
|---|---|---|---|---|
| `in_end_s` | f | s | 0〜36000 | 0（0＝フェードインなし。曲頭 0 からここまで） |
| `out_start_s` | f | s | 0〜36000 | 0（0＝フェードアウトなし） |
| `out_ms` | f | ms | 1〜120000 | 5000 |
| `shape_in`・`shape_out` | e | — | `edit_fade` と同じ 5 種 | `s_curve`／`exp`（曲尾のフェードは dB で直線に近い `exp` が既定） |
| `floor_db` | f | dB | −144〜−60 | −120（`exp` の到達点。その後は厳密に 0） |

- マスターのフェードは本来「最終リミッターの後・ディザの前」に置くもの（リミッターの前で絞ると、絞るにつれてリミッターの掛かりが変わり音色が動く。後で絞ればそれが無い）。**その位置は不変領域なので、既定ではスロット 5 に置く**（最終 `limiter` の前）。正しい位置に置く案は PM_PLAN OD-12。スロット 5 に置いた場合に起きること（フェード中に GR が減る）を記録の注記に固定で書く
- 指揮書からはトラック・バスにだけ置ける（OD-3）。トラックの区間ゲインは既存 `gain`／FB2 の `gain_curve` が正で、`fade` は「曲頭・曲尾の 1 回」に限った簡便な型
- テスト：(1) 両方 0 でビット一致 (2) 包絡が形どおり（±0.01 dB）、`out_start_s`＋`out_ms` より後は厳密に 0 (3) 途中からの描画が一致 (4) フェードの外はビット一致
- 依存：BB-05（形の関数）

## T12-05 ノーマライズ

**編集段の op `edit_normalize`（クリップ・ステムの静的ゲイン）**｜D（カタログ：「loudness_gain と地続き」）｜W4｜S｜Codex
マスターの目標合わせは既存 `loudness_gain`＋検証（変えない）。本件は**取り込んだ素材の水準を揃える**ための op。

| id | 単位 | 範囲 | 省略時 |
|---|---|---|---|
| `mode` | 列挙 | `peak`／`true_peak`／`lufs_i`／`lufs_active`／`rms` | （必須。`lufs_active`＝ゲート付きで、そのトラックが鳴っている区間だけの積分値） |
| `target` 値 `to_db` | dBFS／LUFS | −60〜0 | （必須。既定を持たない：水準は指揮の判断） |
| `max_gain_db` | dB | 0〜40 | 20（上げる上限。雑音だけの素材を持ち上げない） |
| `ceiling_db` | dBTP | −12〜0 | −1（`lufs_*`・`rms` で上げた結果、トゥルーピークがこれを超えるなら、超えない量に抑える。抑えたことを記録） |
| `scope` | 列挙 | `clip`／`track`／`group` | `track`（`clip`＝クリップごとに別のゲイン。`group`＝`group` のトラック全体を 1 つの素材として測り、**同じゲイン**を全員に＝相対バランスを保つ） |
| `group` | トラック ID の配列 | 最大 32 | 空 |

- 台帳に書くのは静的ゲイン（dB）と、測った値（前・後）。素材は書き換えない。**リミッターは掛けない**（ゲインだけ）。測定は既存の BS.1770 実装を呼ぶ（MS3）
- 複数の指揮書・再適用で二重に掛からない：op は「測った前の値→目標」の差を記録し、同じ素材・同じ op なら同じゲイン（冪等）
- 正典：ITU-R BS.1770-4／EBU R 128・Tech 3341／3342（既存実装が準拠）
- テスト：(1) 各 `mode` で、適用後の実測が `to_db` ±0.05 dB（`ceiling_db`・`max_gain_db` に当たらないとき） (2) 当たったとき：超えない量に抑え、記録に理由 (3) `group`：仲間どうしのレベル差が処理前後で同じ（±0.001 dB） (4) 無音の素材：ゲイン 0 と記録（−∞ から計算しない） (5) 同じ op を 2 回適用しても結果が同じ (6) 含まない指揮書はバイト同一、マスターの検証結果の定義は不変（MS1）
- 依存：BB-18（台帳の欄だけ。派生クリップは作らない）

## T12-06 レベラー／ラウドネスコントロール

**mix 段の op `level_phrases`（句ごとに水準を揃える、階段状のフェーダーの線）**｜D｜W4｜M｜Codex｜TV（主役に書けば E3。既存の規則）
T01-11 `ride`（連続的に追う、秒以下の動き）とは別：こちらは**句・段落の単位**で、句の中は動かさない（ダイナミクスを潰さない）。語り・台詞・長尺の素材の均しが本来の用途。

| id | 単位 | 範囲 | 省略時 |
|---|---|---|---|
| `to_lufs` | LUFS | −40〜−6 | そのトラックの `lufs_active`（＝全体の水準は変えず、句の間の差だけ縮める） |
| `amount` | 0..1 | 0〜1（範囲可） | 0.7（各句を目標へ寄せる割合） |
| `range_up_db`・`range_down_db` | dB | 0〜18（範囲可） | 6／6 |
| `pause_ms` | ms | 100〜3000 | 400（これ以上の無音〈活動レベル比 `gate_below_db` 未満〉で句を区切る） |
| `min_phrase_ms` | ms | 200〜10000 | 1000（これより短い句は前の句に付ける） |
| `gate_below_db` | dB | −72〜−20 | −40 |
| `transition_ms` | ms | 20〜2000 | 200（句の間の無音の中で次の値へ移る。無音が短ければその長さまで） |
| `measure` | 列挙 | `lufs_short_max`／`lufs_phrase`／`rms` | `lufs_phrase`（句の中の積分値） |
| `noise_floor_guard_db` | dB | 0〜24 | 12（句の水準が雑音床〈無音区間の水準〉からこの差以内なら、上げない） |

- `target` はトラック ID。`section` を書ける。同じトラックの `duck`／`gain`／`gain_curve`／`ride`／`breath` とは既存の規則で 1 本に合成
- アルゴリズム：活動区間の検出 → 句に区切る → 句ごとの水準（既存の BS.1770 実装）→ ゲイン＝clip(`amount`×(目標−水準), −down, +up) → 句の中は一定、移りは無音の中 → オートメーション 1 本。**移りが発声の中に掛からないこと**が要点（無音が足りなければ、移りを次の句の頭の前までに終える）
- 記録：句の一覧（時刻・水準・ゲイン・上げなかった理由）、処理前後の句の水準の幅（最大−最小、標準偏差）
- 正典：ITU-R BS.1770-4／EBU Tech 3341。**Auphonic・iZotope の方式は読まない**（上の定義で自己完結）
- テスト：(1) 6 句（水準が −30〜−14 LUFS でばらばら）の合成素材：処理後の句の水準の幅が (1−`amount`) 倍 ±0.5 dB (2) 句の中のゲインが一定（変動 0） (3) 移りが全部、無音区間の中（発声区間でゲインが動かない） (4) 上下限・雑音床の保護が効く (5) `level_phrases` を含まない指揮書はバイト同一 (6) 点列が再現一致
- 依存：BB-03、BB-14

| `--match` | `on`／`off` | `on`（試聴ファイルの音量を元と合わせる。FB2 の `listen pack` と同じ規則。**FB2 が正**） |

- 符号化器：**既存の検証が使っている経路をそのまま呼ぶ**（SPEC の FFmpeg 利用の規定に従う。新しい符号化器・ライブラリを足さない。無い符号化器は「使えない」と出して飛ばす。既存と同じ）。符号化器の版・引数を記録
- 出力（JSON）：コーデック×ビットレートごとに、復号後のトゥルーピーク（と元との差）、積分ラウドネスの差、**差分信号**（符号化遅延を相互相関で揃えて引いたもの）のレベルと 1/3 oct スペクトル、帯域の上限（符号化で切られた周波数）、プリエコーの指標（過渡の前 20 ms の差分エネルギー）、正規化の模擬の結果（下がる量、下げた後のピーク）
- `--out`：復号した音（音量合わせ済み）・元・差分の 3 本を、抜粋ごとに。`listen pack` と同じ並べ方・名前の規則
- **リファレンスにしない**：他人の曲をこの道具に通した結果は保存しない（`--audio` で渡した音の復号結果は `--out` を書いたときだけ、そこに出る）
- 正典：ITU-R BS.1770-4 Annex 2（トゥルーピーク）／AES TD1004（配信ラウドネスの勧告）／各コーデックの仕様は読まない（外部の符号化器を使うだけ）
- テスト（MS に加えて）：(1) 符号化器が 1 つも無い環境：明示的に「使えるものなし」、終了コードは成功（下見は止めない） (2) 可逆の往復（試験用に FLAC を通す隠し経路）：差分 ≤ −120 dBFS、遅延合わせが 0 サンプル (3) 遅延合わせ：既知の遅延を持つ模擬の符号化器で ±0 サンプル (4) 復号後トゥルーピークが、既存の検証のコーデック往復の値とビット一致（MS3） (5) `--normalize-lufs`：下がる量＝max(0, 積分−目標) ±0.01 dB (6) `--out` 無しで何も書かない
- 依存：既存の検証のコーデック往復、FB2 の `listen pack`（確定形）、BB-25

## T12-08 統合メータリング

**下見コマンド `direction query meters`（時系列の数値）＋GUI のメータ画面（表示だけ）**｜D（カタログ：「判定ではなく観察系」）｜W4｜M｜Codex

`direction query meters`：`--project`、`--target`（`master`／`trk_<stem>`／バス ID）、`--section`、`--what`（複数可）、`--step-ms`（10〜1000、既定 100）、`--max-points`（既定 2000。超えるなら `step` を自動で広げ、その旨を出す）。

| `--what` | 中身（時系列） | 定義 |
|---|---|---|
| `loudness` | モーメンタリ・ショートタームの LUFS、積分値、LRA | 既存の BS.1770／EBU 3342 実装（MS3） |
| `peak` | サンプルピーク、トゥルーピーク（区間ごとの最大） | 既存 |
| `rms_crest` | RMS、クレストファクタ（300 ms 窓）、PLR／PSR | 既存の定義があれば既存、無ければ本件で定義して docs に書く |
| `spectrum` | 1/3 oct（または 1/6・1/12）のレベルの時系列、長時間平均、最大保持 | ウェルチ法、ハン窓、重なり 50 % |
| `spectrogram` | 時間×周波数（対数 96 帯）のレベル | T10-10 が使う |
| `correlation` | 相関係数の時系列、帯域別（T12-02 と同じ） | T12-02 |
| `vectorscope` | ゴニオメータの要約：区間ごとの M/S のレベル、主軸の傾き（左右の偏り）、広がり（S/M 比）、**点群そのものは既定で出さない**（`--points N` で間引いた点を出す） | 本件で定義 |
| `balance` | L/R のレベル差の時系列 | — |
| `dynamics` | 区間ごとの短時間ラウドネスの分布（ヒストグラム） | — |

- GUI（W4）：スペクトラム、スペクトログラム、ラウドネス履歴、相関計、ベクトルスコープ、ピーク。**表示している数値は全部 `query meters` の出力そのもの**（GUI 側で別計算をしない。顔の等価性）。再生位置に同期した表示は、先に計算した時系列を読むだけ
- **しきい値の色分け・「赤」を作らない**（判定ではない）。プロファイルの目標値の線は、**読むだけ**で重ねて描ける（既存の検証結果の表示と同じ値）
- 正典：ITU-R BS.1770-4／EBU Tech 3341・3342／Welch 1967
- テスト（MS に加えて）：(1) 既存と同じ量（積分 LUFS、TP、LRA、相関）がビット一致（MS3） (2) `spectrum`：ピンクノイズで 1/3 oct が平坦 ±0.5 dB、1 kHz 正弦で該当帯だけが立つ (3) `vectorscope`：L＝R で傾き 0・広がり 0、片側だけで傾き ±45°、L＝−R で広がり最大 (4) `--max-points` の間引きが最大値を落とさない（ピーク系は区間の最大を保つ） (5) GUI の表示値と CLI の値の突合せテスト（同じ JSON を読んでいることの確認）
- 依存：BB-06、BB-25、T12-02

## T12-09 トーンバランス比較

**下見コマンド `direction ref balance`**｜D（カタログ：「ref compare の発展」）｜W4｜S（T02-08・T02-09 の測定の後）｜Codex

| 引数 | 範囲 | 省略時 |
|---|---|---|
| `--project`／`--audio` | — | — |
| `--refsheet`／`--ref-kb`／`--ref FILE…` | リファレンスの集合（既存の ref study の成果、または音声） | **必須**（同梱の「ジャンル目標」は持たない。T02-09 と同じ） |
| `--bands` | `4`／`third`／`sixth` | `4`（低 <250／中低 250〜2k／中高 2k〜8k／高 >8k Hz の 4 帯。`third`＝1/3 oct） |
| `--section` | セクション ID／`loudest`（最も大きい 30 s） | 全体 |
| `--normalize` | `lufs`／`mid_band` | `lufs`（比べる前に水準を揃える基準） |
| `--over-time` | 秒 | off（書けば、その窓で時間別にも出す） |

- アルゴリズム：T02-08 と同じ長時間平均スペクトル → 帯ごとのレベル（全体比）。リファレンス集合の帯ごとの分布（中央値・四分位・最小最大）に対し、対象がどこにいるか。加えて**低域のクレスト**（<250 Hz の帯のピーク/RMS。低域の締まりの代理量）も同じ形で
- 出力（JSON）：帯ごとの「対象の値・リファレンスの中央値と範囲・範囲の内か外か・外なら何 dB」、当てになり度（リファレンス 3 曲未満は `low`）、時間別（指定時）。**「合わせるべき」とは言わない。EQ の候補も出さない**（候補は T02-07・08・09 の仕事。本件は見るだけ）。GUI は帯の範囲の帯と対象の線を重ねて描く
- 既存 `ref compare` は変えない。重なる量があれば既存の値を使う（MS3）
- **リファレンスの音は保存しない**（測った値だけ）
- テスト（MS に加えて）：(1) 対象＝リファレンスの 1 曲：全帯が範囲内 (2) 対象の低域を +6 dB した素材：低の帯だけ「外・約 +6 dB」 (3) リファレンス無しは明示エラー (4) `third` の値が T02-08 の測定と一致
- 依存：T02-08 のスペクトル測定、BB-25
