### 委任による確定（2026-11-13、3回目のセッション）

オーナーは、`UPSTREAM_REPORT.md` に残っていた質問の全てについて「上流設計者に決めさせる」と決定した。以下は、その委任に基づいて上流設計が最終判断した確定事項である。各決定に理由を添える。

| ID | 質問 | 決定 | 理由 |
|---|---|---|---|
| D-034 | Q-01 | 実装スタックは、コア・CLI・MCP を Python（3.11 以上）、ネイティブ DSP 核を C++17（C ABI、CMake）、GUI を TypeScript ＋ React ＋ Vite の Web SPA とする。ネイティブ核は M4 で導入し、M1〜M3 は Python と FFmpeg だけで動かす | 解析・測定・分離の採用候補が全て Python で、Airwindows が C++ だから。GUI は静的ファイルとして出力でき、Pages のデモにそのまま載る構成にした |
| D-035 | Q-02 | GUI の「エージェント機能」とは、外部エージェント（CLI / MCP）との連携（操作の追従、提案の承認と却下、操作履歴）を指す。v1 の GUI は LLM との対話パネルを内蔵しない。決定的なプランナーはエージェント機能に含めず、デモでは事前計算の結果として見せる | API キーの保管と LLM への通信を GUI に持ち込まないため。コア自身が LLM を呼ばない原則とも揃う |
| D-036 | Q-03 の 1 番目 | 聴き比べの「処理前」は、12 ステムの単純合算（ゲイン 0 dB、ステレオのまま、処理なし）とする。既存のフルミックスは参考として併置する | 入力と同じ素材から作るので、処理後との差が本ツールの処理だけに由来する。フルミックスはステムの合算と一致しないので、基準にすると差の由来が混ざる |
| D-037 | Q-03 の 3 番目 | conform 済みセットにある `other` と `no_vocals` は、公式サンプルの入力にも、処理前の合算にも含めない。公式サンプルの入力は 12 ステムとフルミックスとする | 素材側の制作記録で出自を特定できた。どちらも Suno のステムではなく、ステムを合算して作った派生ファイルである（`other` はボーカル・ドラム・ベース以外の 8 ステムの合算、`no_vocals` はボーカル以外の合算）。含めると同じ音を二重に足す |
| D-038 | Q-04 | 公式サンプルはフル尺で公開する。加工後の全種別を公開し、入力ステムも公開する。試聴用の音声（MP3 320 kbps）と Mix Report はリポジトリの `samples/public/` に、ロスレスのマスターと入力ステムは Release 添付に置く。入力ステムは git の履歴に入れない。曲名はそのまま表記し、歌詞はリポジトリに載せない。公開の直前に監査の工程（M9）で権利条件を一次資料で再確認し、確認できなかった項目だけ公開を見送る | 有料プランの契約期間中の生成物は商用利用可、という調査結果が前提。約 99 秒の短い曲で、抜粋にするとセクション間の評価が聴けない。入力ステムの公開は「同じ入力から同じ出力を再現できる」という主張の裏付けになる |
| D-039 | Q-05 | リファレンスは利用者がプロジェクトごとに登録する。v1 では、市販曲から得た統計をリポジトリに同梱しない。同梱の可否は M10 で、公開監査を通して改めて判断する。公式サンプルはリファレンスを登録せず、汎用の目安とジャンル prior で処理する。聴感評価の評価者は、オーナーとオーナーが声を掛けた協力者とする | 統計値だけでも、選曲の責任と権利上の確認が要るため。リファレンスなしでも動くこと自体が、標準の経路として必要 |
| D-040 | Q-06 | サンプルとして用意する種別は 11 種とする。目的関数の軸 5 種（`comfort`、`bass_heavy`、`vocal_forward`、`clarity`、`low_fatigue` を `streaming_universal` で）、媒体の軸 4 種（`comfort` を `apple_music`、`sns_hot`、`cd`、`club` で）、2軸の合成 2 種（`club_impact × club`、`bass_heavy × club`）。主サンプルは `comfort × streaming_universal`。強度は全種別で 0.5 にそろえる | 全ての組み合わせ（数十通り）でなく、2つの軸それぞれと合成の3方向を聴ければ、製品の構造が伝わる。目標が同じ −14 LUFS の媒体は音の差がほぼ出ないので、音声でなく検証結果の表で示す |
| D-041 | Q-07 | ニューラルモデルによる高域補完は標準経路に入れない。利用者が明示的に有効にしたときだけ使えるオプションとし、使った場合は Mix Report に記録する。既定は決定的な DSP による補完 | 製品の約束が「実ファイルへの決定的な処理であり、生成で音を作り直さない」ことにあるため |
| D-042 | Q-08 | 最初の対応 OS は Windows 10 / 11（x64）。コア・CLI・MCP は OS に依存しない書き方をし、Linux と macOS は公開（M9）までに動作を確認する。GPU が要るのは分離だけで、基準は NVIDIA の VRAM 10 GB 級。CPU で動く軽量モデルを公式カタログに必ず持つ | 開発と検証の環境が Windows であるため。AI エージェントの利用環境は Linux と macOS が多いので、公開時点では動く必要がある |
